Notes on serving-time feature availability:
click_history for each impression is truncated to articles clicked strictly
before that impression's timestamp (enforced during preprocessing), so no
future-click information leaks into features. Train/val/test are split
purely by time (never randomly) with strictly increasing, non-overlapping
time windows, verified above. One bug caught by this exact test during
development: MIND's impression_id is only unique *within* a single
behaviors.tsv file (train/dev/test each restart numbering from 1) — after
combining the train+dev bundles for the temporal split, unrelated
impressions from different source files briefly collided under the same ID.
Fixed by prefixing impression_id with the split name before combining
(the official competition test set is exempt, since Codabench expects its
original unprefixed numeric IDs).
