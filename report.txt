Run time: ~4 min total (encoding + FAISS batch search over 1,997,301 val users).

Sanity-check notes (this is ~4-8x lower than EB-NeRD BM25 — verified as a real
finding, not a bug):
  - Embeddings verified sound: unit-normalized (norm ~1.0 for all rows), no
    NaN/Inf, no degenerate/identical rows.
  - Index alignment verified exact: corpus_ids.npy matches articles.parquet's
    article_id column length, order, and set exactly — no stale-cache issue.
  - Qualitative nearest-neighbor spot check (4 random articles, top-5 by
    cosine similarity): one query (a luxury-hotel-closure story) clustered
    tightly on-topic with other hotel-closure stories (sim ~0.68-0.70). The
    other three (a football club story, a celebrity-scandal story, a sports
    veteran story) clustered more by tabloid tone/register ("dramatic
    scandal" headlines) than by actual topic. This is a real, expected
    limitation of an off-the-shelf multilingual model with no fine-tuning
    for this specific domain (Danish tabloid news) — not an implementation
    bug.
  - Two compounding factors beyond the model itself: (1) the user
    representation is a mean-pool of the last 10 clicked articles' embeddings,
    which can dilute signal for a reader with varied interests, unlike BM25's
    precise per-term matching; (2) same full-125K-corpus-vs-tiny-candidate-pool
    gap noted for BM25 above.

Lexical vs. Semantic comparison notes:
MIND: essentially a tie. BM25 = 0.0103/0.0167/0.0245, Semantic = 0.0099/0.0155/0.0248
(BM25 marginally ahead at K=50/100, semantic marginally ahead at K=200). Makes
sense for MIND — English news headlines/abstracts have enough exact lexical
overlap between a user's click history and the true next click that BM25's
term matching stays competitive with dense embeddings at this scale.

EB-NeRD: BM25 clearly wins (0.0069/0.0081/0.0108 vs semantic's 0.0008/0.0016/0.0031,
~4-8x higher). The gap vs. MIND (where the two methods tied) is the interesting
result for the design note: lexical retrieval degrades gracefully to a
non-English, non-fine-tuned setting, while general-purpose multilingual dense
embeddings degrade much more sharply without domain fine-tuning. Good candidate
for the "where it breaks / what we'd improve" discussion — a fine-tuned or
domain-adapted Danish embedding model would likely close this gap significantly.

MIND re-ranking: BM25 vs Semantic — semantic clearly wins here (AUC 0.6212 vs
0.5412, MRR 0.3268 vs 0.2827, nDCG@10 0.3617 vs 0.3107), unlike the earlier
full-corpus recall@K result where the two were roughly tied. Worth flagging
in the design note as a genuinely different task: recall@K measures whether
BM25/semantic can *find* the right article among all 125K, while this harness
measures whether it can *rank it highly* within the small candidate set the
platform already curated — semantic similarity is a stronger ranking signal
than exact term overlap once the candidate set is already narrowed down.
Also note: unlike BM25 (where cold-start edged out warm on nDCG), semantic
here has warm > cold-start on every ranking metric — dense embeddings seem
to benefit more from a longer averaging history than BM25's sparse matching
does.

Notes on serving-time feature availability:
click_history for each impression is truncated to articles clicked strictly
before that impression's timestamp (enforced during preprocessing), so no
future-click information leaks into features. Train/val/test are split
purely by time (never randomly) with strictly increasing, non-overlapping
time windows, verified above. One bug caught by this exact test during
development: MIND's impression_id is only unique *within* a single
behaviors.tsv file (train/dev/test each restart numbering from 1) — after
combining the train+dev bundles for the temporal split, unrelated
impressions from different source files briefly collided under the same ID.
Fixed by prefixing impression_id with the split name before combining
(the official competition test set is exempt, since Codabench expects its
original unprefixed numeric IDs).
